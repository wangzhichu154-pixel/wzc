# 人民币 500 万单股票持仓退出规则

## 用户确认的业务规则

- 范围：指定交易账户中某一只股票的已核对持仓。
- 阈值：持仓市值 **≥ 5,000,000 CNY**。
- 动作：停止该股票新增买入、撤销该股票全部未终结买单，随后卖出全部持仓。
- 不解释为利润、股票总市值、成交量或获准买入的金额。原有资金、仓位和损失上限继续有效。

美股工程估值口径为：

`已核对整数股数 × 新鲜 USD 买一价 × 新鲜 USD/CNY（每美元对应人民币数量）`

采用 Decimal 精确比较，等于阈值即触发，不先把市值四舍五入。买一价格是保守估值口径，不保证整笔持仓能按该价格成交。汇率变化本身也可能导致人民币市值达到阈值。CNY 与 CNH、正向与反向汇率必须明确区分，不能静默替换。

## 已实现的独立规则模块

代码为 `execution/cny_exit_policy.py`，不加载 AI、不连接 broker，不改变现有 live 禁用状态。

`evaluate()` 接受不可变配置、上次退出状态、完整持仓/订单对账快照、股票及 FX 时间标记，产生内部的退出目标和撤单需求。没有构造可直接发送的 broker 订单，也没有绕过风控的发送许可。

| 阶段 | 规则行为 |
|---|---|
| MONITOR | 数据完整、健康且低于阈值；本规则不阻止买入，其他风控仍必须检查 |
| WAIT | 数据/对账异常、不可交易或未知发送；阻止新增买入，不增加卖单 |
| CANCEL_BUYS | 已触发，维持零仓目标，要求取消所有已知未终结买单并等待终态和成交核对 |
| EXIT_WORKING | 新买单清除后，使用更新的实际持仓减去全部非终结卖单预留，得到最多可新增卖出量 |
| FLAT_LOCKED | 已核对持仓为零、没有任何残余订单，继续阻止策略自动买回 |

一旦触发，市值回落或 FX 数据失效都不撤销零仓目标。后续减仓仍要求新鲜股票行情、有效账户/市场状态和同步风控。撤单过程中迟到的买入成交，以新快照持仓重新纳入退出，不使用触发时冻结的股数。

未确认撤单的卖单仍占用数量；未知发送结果阻止追加卖出。卖单预留超出持仓或零仓仍有卖单时，请求清除这些残余卖单并等待，不把负的可卖余额简单截成零后宣称成功。

模块默认股票/账户新鲜度上限为 2 秒、汇率为 5 秒，属于待实测的数据源配置，不是延迟承诺或实盘授权。`Mark.asof_monotonic_ns` 必须由数据适配器依据源时间年龄保守转换，不能消费时直接填“现在”延长旧数据有效期；跨进程/重启不能复用旧单调时钟标记。

## 接入执行器前必须完成的工作

1. **USD/CNY 实时源**：当前新增 IBKR BidAsk 入口只接受 USD 股票，不包含 FX 订阅；真实 CNY 源、权限、时间质量尚未接入验证，不能拿假汇率启用此规则。
2. **持久化与重启**：执行所有动作前持久化 `ExitState`，恢复时先加载锁存状态，再完成 broker 对账。当前纯模块只测试状态序列化往返，没有提供退出锁存数据库或宕机恢复集成。禁止把默认 `triggered=False` 用作已触发账户的重启状态。
3. **买入路径硬拦截**：所有策略/客户端对该账户、该合约的买入必须遵守锁存；模型没有解除接口。当前 Paper 执行器尚未导入此模块，不能认为仅添加文件就已生效。
4. **全量订单与成交核对**：快照必须包括本地预留、未知发送、未终结订单和最新唯一成交。普通只读账户探针不提供原子、完整的交易对账保证。不能用不完整快照宣称无买单或已清仓。
5. **订单管理与风险**：零仓目标具有幂等语义，不是每次评估都发送一个新卖单。每次发送前通过现有同步风控和数量预留；成交去重、部分成交、撤单竞争继续由订单管理器处理。
6. **价格和失败策略**：实际卖出价格、滑点上限、撤改单节奏、拒单/停牌/断线告警和重试边界仍须与完整策略一起实施。不以阈值条件承诺立即成交，也不盲目重发未知状态订单。
7. **恢复买入**：暂按受控 Supervisor 复核解锁，不允许 AI 自行重置。完整恢复流程尚未实现。本模块没有重置 API。

指定股票退出不能通过全账户 `globalCancel` 实现，以免误撤其他股票订单。跨客户端订单若无法控制，必须阻止启用或转入明确运维流程。
