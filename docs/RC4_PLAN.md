# rc.4 改造范围与验收计划

基线为已交付 rc.3。延续原有 C++ 核心、Django、IBKR Paper 适配及严格授权边界；不更改任何真实资金权限，不为产生交易而降低成本或风控门槛。

1. **账户估值与行情状态分离。** 完整会话收盘后，真实平仓、无挂单且现金账本对平的账户可以计算结算净值。曾有风险敞口而缺少有效估值时，回撤路径仍不完整；不能凭最终平仓消除缺失风险。旧报价有效性不变。
2. **评估由底账复核。** 完整锁定测试集、各会话和每个压力情景必须匹配。汇总数值、状态布尔值不能单独证明通过；旧证据不满足新核验要求时仅保留历史展示。
3. **一条命令完成离线工作。** 安装预声明政策→训练→登记→预测门槛→回测→模拟门槛；每阶段保存输出、返回码与校验收据。恢复只能使用原始同一请求，禁止借恢复重新消费测试集。门槛拒绝与程序失败分别记录。
4. **模型库可恢复。** 完整、一致、带校验的备份，拒绝符号链接、恶意归档与覆盖业务目录；恢复后交易指针隔离，不能因恢复文件自动重启交易。
5. **展示真实失败原因。** 区分行情报价、账户净值、回撤完整性、无成交及发布状态；保持只读与服务端权限。
6. **强化安全发布门。** 同镜像摘要的扫描结果与实际运行库清单必须一致；独立检查已知上游漏洞，避免发行版漏洞库差异造成假绿灯。

本轮使用新的 2026 年 10 月合成会话（生成 seed 46）验证完整流水线，保留旧数据与模型，不将测试调参或合成收益作为市场盈利证明。实际执行结果另行记录，本文不是验收通过声明。
