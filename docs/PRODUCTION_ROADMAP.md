# Production v1.0.0 改造路线图

这是执行路线，不是完成声明。每阶段检查上一阶段遗留项。

## 架构决策

- C++20：ITCH 解析、序列检查、订单簿、报价、同步风控、订单状态及确定性回放；热路径不经过 Web/DB。
- Django 5.2 LTS：服务端渲染的响应式控制台、成熟用户认证、CSRF、ORM、管理后台、版本化 API；避免为门户无必要地拆分前后端服务。
- PostgreSQL：正式持久化；Redis + Celery：异步任务、共享限流；SQLite 仅用于隔离测试和本地开发。
- Nginx：入口、TLS 与静态资源；Prometheus：指标；Docker Compose：可重复部署；GitHub Actions：CI。
- 外部依赖未配置时明确返回不可用；不以 Mock、固定图表或假订单代替真实业务。

## 阶段与完成门槛

| 阶段 | 实施 | 门槛 |
|---|---|---|
| 0 审计 | 确认设计为基线、现有资产和缺失项 | 本报告、范围与问题清单可审查 |
| 1 工程基础 | 模块边界、环境配置、依赖、日志、API 约定 | 干净环境安装、配置校验、启动检查 |
| 2 数据与身份 | 迁移、注册、验证、会话、密码恢复、RBAC | 数据约束、跨用户隔离、权限拒绝测试 |
| 3 交易核心 | ITCH、订单簿、报价、风险与回放 | 协议语义、gap fail-closed、风险不变量测试 |
| 4 产品闭环 | 上传、任务、结果、控制台、审计、反馈、开关 | 真实输入到持久结果闭环；错误路径可恢复 |
| 5 执行边界 | IBKR 独立适配与连接配置、Kill/授权隔离 | 编译/接口测试；真实 broker 验收单列 |
| 6 UI 与安全 | 统一响应式界面、错误页、限流、隐私操作 | 页面/权限/CSRF/上传与安全测试 |
| 7 交付设施 | Docker、CI、Nginx、监控、备份脚本 | 构建、迁移、测试及备份恢复检查 |
| 8 Staging | 真实环境与邮件、TLS、性能、安全、恢复演练 | 有实际证据，不能用配置文件代替 |
| 9 Production | 清单、版本、灰度与回退 | 阻塞项归零、受控发布、部署后冒烟 |

## 发布控制

实现采用版本 1.0.0 的候选工程基线；在验收前不创建“已上线”声明。Web 研究功能与实盘交易分别验收。任何实盘开关不能绕过核心同步风控、Kill 锁存或 broker 对账。新增配置和功能开关变更均需权限和审计。
