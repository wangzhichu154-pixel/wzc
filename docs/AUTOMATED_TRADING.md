# 自动交易、成本控制与收益验证

本产品的目标是把报价、成交记账、风险控制和结果验证自动化。代码不能保证盈利；有效策略必须在真实费用、成交条件和不同市场阶段中接受验证。没有真实行情/账户时，不生成真实交易结果。

## 三种运行方式

| 模式 | 输入与执行 | 可观察结果 |
|---|---|---|
| Replay | 授权 ITCH 历史文件，不产生账户成交 | 订单簿、策略决策和确定性 checksum |
| Simulation / 自动运行 | 同一 C++ 策略和风险核心、延迟与队列模型 | 明确标注的模拟成交、费用、库存和净盈亏；各轮是独立实验 |
| IBKR Paper | 独立进程、官方 SDK、实时 ITCH、核实的纸账户和逐笔同步风控 | 满足外部接入条件后的模拟账户订单；当前没有真实账户联调证据 |

Live 仍拒绝。收益评估结果、会员权限或正收益历史样本都不会自动打开真实资金交易。行情停止、序列缺口、未知订单或账户不一致不能以“继续赚钱”为理由绕过。

## 为什么加入成本约束

双边价差不等于净利润。小额交易的最低订单佣金、部分成交、买卖两侧费用和不利价格变化都可能超过捕获的价差。因此定价增加以下参数，金额单位统一为 **1/10000 USD**：

- `fee_per_share_units`：每成交股费用假设。
- `min_fee_per_order_units`：每张有成交订单的最低佣金。
- `slippage_buffer_units`：每股不利成交/价格变化缓冲，仅为报价假设，不能界定实际损失。
- `min_net_edge_units`：每股目标净边际，属于报价目标，不能被展示为已赚收益。

保守单边成本距离：

```text
cost_floor = fee_per_share + min_fee_per_order + slippage_buffer + min_net_edge
half_spread >= max(existing_half_spread, cost_floor)
```

最低佣金全部分摊到可能只成交 **1 股** 的情况。报价 floor 使用相加，故比真实佣金 `max(minimum, per_share × filled)` 更保守；不借预计回扣缩小距离。价格仍按 tick 向被动方向取整，围绕**库存偏移后的参考价**计算，而不是保证每笔相对未来价格都有优势。

例如 1 股 Paper 订单，费用假设 0.01 USD/股、最低佣金 1 USD，再加各 0.01 USD 的缓冲和边际，单边成本距离就是 1.03 USD。这可能远离市场最佳价而长期无成交。应据实检查交易规模和实际费用，不应为了制造成交或好看的收益降低成本假设。

实际模拟佣金按每个订单累计成交量计算：

```text
filled == 0: total_fee = 0
filled > 0:  total_fee = max(min_fee_per_order, filled × fee_per_share)
new_fill_fee = total_fee_after - total_fee_before
```

因此取消未成交订单不产生该模型的成交佣金，后续部分成交只补差额。此简化模型仍不是完整券商费率表；真实交易可能另有路由、卖出监管、借券或阶梯费用。

若成本距离导致合法被动价格不存在，策略会停止报价并请求取消旧订单。它不自动强平已有库存；必须继续检查持仓、估值与风险状态，不能把停止新增成交理解为敞口归零。

## 从界面运行

1. 上传有权使用的 ITCH 记录，在风险设置中设定库存、订单数量、tick 和损失限制。
2. 选择自动做市模拟，填写延迟、费用、最低佣金、缓冲与目标净边际；提交后快照固定。
3. 检查成交数量、实际收取费用、净盈亏、库存、开放订单和报价成本距离。无成交的零盈亏不说明策略有效。
4. 在“收益评估”选择同一参数/模型下的已完成模拟任务，添加额外每股成本压力并保存不可变评估。
5. 有明确研究目的时，再创建周期自动运行任务；重复同一文件不能积累为真实账户复利。
6. Paper 进程必须另行完成 [IBKR 接入条件](IBKR.md)，不能使用历史文件假扮实时行情。

## 收益评估如何避免误判

- 服务端检查账户归属与任务模式，只有成功生成的模拟结果可以参与。
- 相同文件 SHA-256 不重复累计；不同 hash 仍可能是重叠时段，不能据此证明独立交易日或样本外表现。
- 不合并不同风险、执行假设和报价模型版本。旧结果保留，但不追溯改写成新的成本模型。
- 复核 `NetPnL = Realized + Unrealized - Fees + Rebates`，不接受缺失或自相矛盾的账本。
- 压力情景从已有费用后净盈亏中移除全部假设回扣，再扣 `成交股数 × 额外每股成本`；这是没有回扣且成本更高的假设，不重扣原最低佣金，也不表示实际回扣已撤销或已经模拟真实市场冲击。
- 无成交、无效估值、风险熔断、未平仓/开放订单和样本不足都要单独显示。正样本不是实盘授权，也不是利润保证。
- 默认研究门槛至少 5 个不同文件、100 股模拟成交，只是产品检查阈值，不是统计显著性或独立性证明。未建立真实 OOS、成本校准和市场适应性证据时，不声称策略可盈利。
- 不把独立重置账户的模拟结果合计称作连续账户曲线，不计算没有资本/持有期依据的年化收益。

评估记录保存输入任务、行情 hash、参数和模型版本快照；后续账户参数变化不会改写已有报告。账户注销时清除私有研究快照，安全审计按既有保留政策处理。

## Paper 执行的成本配置

`execution/paper.env.example` 新增 `PAPER_SLIPPAGE_BUFFER_UNITS` 与 `PAPER_MIN_NET_EDGE_UNITS`，与既有每股费用、最低佣金一起交给 C++ 核心。新的 Python 接入器要求共享库提供成本配置接口；旧库缺少接口时拒绝启动。

成本参数必须在第一次 arm 前设置；arm、撤销或 Kill 后不能通过改参数重新降低约束。策略本身无权清除 Kill。实际佣金回报、迟到成交和未知订单继续受原有持仓/损益与对账屏障控制。

真实盈利仍取决于行情质量、交易费用、成交概率、逆向选择、库存、竞争和市场状态。当前交付的内容是这些问题的工程控制和可审计验证工具，不是已被证实盈利的交易系统。
