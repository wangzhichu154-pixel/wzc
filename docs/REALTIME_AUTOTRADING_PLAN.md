# 实时 API 自动交易：目标、现状和接入约定

## 已确认的产品目标

交易主循环直接消费实时行情 API，自动筛选、买入、退出和对账；无需人工导入行情文件，也无需逐笔点击确认。模型判断保留为内部审计，不把“输出建议”当作产品终点。历史文件只用于训练、回测、记录和故障复现。

用户将提供自己的判断规则，再据此建立可执行规则基线及经过验证的 AI 模型。尚未收到规则，不能自行发明交易逻辑或宣称训练完成。

退出条件之一是**单只股票持仓市值达到 500 万**。当前理解来自用户对“持仓市值”的澄清；币种，以及全部退出或只减持超出部分，仍待确认，因此没有启用此阈值。它不是 500 万利润，不是股票总市值，也不是获准购买 500 万的仓位限额。

## 本次实际实现

`execution/ibkr_market_stream.py` 新增官方 IBKR SDK `reqTickByTickData(..., "BidAsk", 0, False)` 入口。

- 逐笔回调直接进入有界内存队列，调用消费函数；没有历史行情文件输入，不请求历史 ticks。
- 明确合约 ID、股票代码、主要交易所，向 Gateway 查询合约并验证 USD/STK 身份；核对配置账户是否属于当前会话。
- 明确股票池，当前入口上限 10 个合约，实际订阅数受 IBKR 权益限制；不宣称全球市场覆盖或自动选股已完成。
- 同时保留 Unix 秒源时间、接收墙钟与单调时钟。本地递增序号仅用于接收顺序，不能检测交易所丢包，不能冒充交易所序号。
- 报价源时间过旧、延迟/冻结数据回调、权限错误、断线、静默、倒退时钟、队列溢出或消费前过期都会结束会话；没有自动重连后恢复交易。
- 秒级时间精度意味着不能据此声称亚毫秒行情延迟。静默时保守失效，即使实际只是市场没有报价变化。
- 行情入口只读，未接到订单发送器；真实 API 连接和订阅权限尚未验证。报价本身不证明没有停牌、处于允许交易时段或账户有交易权限。

原有 ITCH 接收器和单标的 Paper 下单程序保留。IBKR BBO 不是 NASDAQ ITCH，不能伪造 ITCH 消息来绕过原有序列、订单簿和交易状态检查。原 ITCH 特征使用交易所日内时间，也不能直接消费 Unix 秒时间戳。新数据源必须配套新的特征合同和验证过的模型。

## 验证与接入命令

以下命令在服务源码根目录运行。未加 `--connect` 时，不读取 SDK、不建立网络连接、不下单：

```bash
python -m execution.ibkr_market_stream
python -m unittest execution.tests.test_ibkr_market_stream -v
```

只有获得真实 Gateway 连接和数据权限后，才执行只读数据联调。安装与 Gateway 兼容的官方 SDK，不在聊天或 Git 中保存密码。连接方式是 TWS/IB Gateway 的 TCP API，并非所有服务都使用一个 API Key。

用实际核验的合约信息创建本机 `universe.json`。下面是**不可直接运行的配置结构**，不是行情文件、默认股票推荐或真实合约 ID：

```json
[
  {"con_id": null, "symbol": "替换为股票代码", "primary_exchange": "替换为主要交易所"}
]
```

明确设置 `IBKR_ACCOUNT`、`IBKR_HOST`、`IBKR_PORT`、独立的 `IBKR_MARKET_CLIENT_ID`，并保持 `IBKR_EXECUTION_MODE=readonly`。当前入口只接受明确匹配的 Paper 会话；DU 前缀和端口本身不构成完整 Paper 权限证明。

```bash
python -m execution.ibkr_market_stream --connect --universe universe.json --seconds 60
```

该命令输出的是实时数据接入诊断，不是最终自动交易 UI，也不是实盘启用命令。流式库接口接受内存消费函数，后续策略不需要再从 stdout 或文件读回行情。真实联调需保留失败原因、数据许可、时间质量和合约映射记录。

本次新增测试使用明确的 fake SDK 回调，覆盖合约和账户身份、时效、两种 SDK 错误签名、延迟行情、权限拒绝、断线、静默、队列溢出和消费者失败清理。本次执行层回归共 93 项测试通过（含新增 12 项测试），无跳过；Ruff 通过。消费者当前须迅速返回，控制台输出或阻塞消费可能延迟退出，接订单执行前还需独立监督和非阻塞消费。上述测试不证明真实券商连接成功。测试日志存放在 `docs/evidence/realtime-api/`。

## 完整自动交易仍需完成的部分

| 阶段 | 实施内容 | 完成标准 / 当前阻塞 |
|---|---|---|
| 规则形式化 | 入场、退出、周期、仓位、止损、禁交易条件；区分规则标签与未来收益标签 | 待用户规则，不能用聊天描述臆造可盈利策略 |
| 股票范围 | 市场、品种和账户授权白名单；宽范围筛选后订阅候选，持仓优先保留订阅 | 默认美股起步；多市场须分别核对数据许可、币种、时区、交易日历与额度 |
| 实时数据 | 真实 API 权限、断线、数据质量、停牌/交易状态、采集和训练数据合同 | 本次提供 BidAsk 接入代码；真实联调未执行 |
| 训练 | 规则基线、真实授权数据、因果特征、时间切分、重叠标签隔离、独立测试与成本压力 | 数据与规则未提供；未进行新的训练 |
| 组合执行 | 多股票目标仓位、共享资金预留、账户风险、订单幂等、部分成交、撤单竞争 | 原程序为单标的做市方向过滤，不能直接当成多股趋势策略 |
| 自动退出 | 卖出目标数量、未成交卖单预留、先撤买单、部分成交继续核对、退出锁存 | 500 万规则币种/动作待确认；触发时不保证能按触发价成交 |
| 宕机恢复 | 持久目标、Broker 权威订单/持仓/资金核对、未知发送状态处理 | 重连不等于恢复许可，不可盲目重发或简单清空账本 |
| 模拟闭环 | 实时接入、模型推理、独立风控、真实 Paper 提交/撤销、成交和对账 | 无需逐笔手动确认；须实际记录回报和异常测试结果 |
| 实盘 | 独立实盘执行门槛、明确账户/资金/标的/损失限额和停止规则 | 当前 live 仍禁用；模型不得扩大授权或修改限额 |

自动卖出不是“检测到条件就立即宣称已经卖完”。退出状态应持续跟踪 `EXIT_REQUESTED → CANCEL_BUYS → SELL_PENDING/PARTIALLY_FILLED → FLAT`，遇到拒单、停牌或断线进入待处理状态；在完成之前不再买回同一股票，恢复条件必须明确。持仓市值可按买一可出售价格保守估值，具体口径、跨币种汇率时效及退出滞回需要与规则一起确定。

## 当前验收边界

- 未收到用户交易判断模型，没有训练出所谓“用户专属 AI”。
- 未连接真实 Gateway，未查询真实账户，未发送任何 broker 订单。
- 未实现全球股票自动扫描、多标的自动执行或新的桌面开关。
- 没有盈利保证；预测收益必须覆盖交易成本且通过样本外验证。
- 正常自动交易可以在已授权范围内不逐笔确认；实盘账户、资金与风险额度仍须明确授权，不能由模型自行决定。
