## 必要假设与边界

- Linux、C++20、Python 3.12；本环境有 3 个可见 CPU 核，采用 CPU Ridge，不增加 GPU 或大语言模型服务依赖。
- 模型预测指定未来窗口的中间价收益，单位 bps；它不输出未经校准的盈利概率，也不把新闻发布时间等同于实际可获得时间。本次没有可靠新闻源，不使用新闻特征。
- 输入要求单标的、完整会话、2 字节长度前缀的 ITCH 5.0 文件。全市场多标的、PCAP、缺会话开头、行情恢复和自定义预处理不是隐式支持的能力。
- ITCH 日内时间、离线逻辑时间和 broker monotonic 时间分别记录。没有接收时间时不能计算真实行情源延迟；没有券商连接时不能报告 Tick-to-ACK。
- 训练数据权利是操作员声明，软件不能独立证实授权；合成数据的 provenance 全链保留，注册用户或模型不能自行更改资金风控限额。
- 研究输出不是订单指令。报价、数量、持仓预留、资金与权限检查仍由独立模块执行。模型等待可能留下库存；本版本没有获授权的自动市价清仓流程，必须显示残余风险。
- 按会话独立平仓起点回测，不假定期末自动清仓，不将这些结果拼成连续真实账户收益曲线。缺资本基数不编造百分比回报和换手率。

## 改造路线与验收点

1. 保留现有生产基础和 C++ 核心，先审计数据与执行权限。
2. 从 C++ 实际订单簿导出因果观测；再次导出核对源文件与 CSV 的绑定。
3. 固定特征/标签与成本门槛，完成 train/validation/test 及 walk-forward，保存数值模型和训练日志。
4. 将预测接入方向过滤器，执行同一 C++ 成交/风险仿真和预声明成本、延迟压力。
5. 增加获批模型加载、现金预算及 Paper 失效处理；所有门槛失败保持停止。
6. 保存版本、失败评估、漂移和再训练记录，并提供运营只读界面。
7. 运行协议、训练、模型、风险、API、浏览器和容器检查，记录真实证据。
8. 真实授权数据、IBKR Paper 对账及正式环境验收通过后再评审实盘能力；本次不跳过这些步骤。
